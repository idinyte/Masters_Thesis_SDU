\section{Implementation 1}


A PyBullet environment has been created; it consists of a table, a softball, and a Robotiq 140 gripper (Fig. \ref{fig:pybullet_env_design_one}). The table and gripper were imported using a Unified Robot Description Format (URDF), an XML-based file format used to describe the physical and kinematic properties of a robot. The softball was created using open-source 3D modeling software - Blender. The blender file exported as .obj provides only the surface mesh. To obtain the volumetric mesh needed to simulate the soft body, open-source software - GMSH was used.

\bigskip \noindent
The gripper is controlled by a single motor using position control. The stroke range of the gripper was calculated by measuring the distance of a fully closed and fully open gripper. The stroke range turned out to be from 0 to 0.127 simulation distance units. A function that controls the Robotiq gripper based on distance instead of a motor angle was created by linearly spacing 100 points of the gripper's stroke range, measuring the angle of the motor and the distance between the fingerpads in simulation, and fitting this data using a polynomial (Fig. \ref{fig:robotiq_polynomial_fit}).

\bigskip \noindent
In order to control the gripper opening in the simulation, an equivalent function needs to be created for the exoskeleton. Then the calculated exoskeleton gripper opening distance could be sent and applied directly to the simulation in real time. The distance between exoskeleton finger pads can be calculated using simple trigonometry (Eq. \ref{eq:trigonometry_distance_prototype1}, Fig. \ref{fig:trigonometry_distance_prototype1}). This distance calculated from the motor positions is normalized and then scaled to the gripper's stroke range in the simulation before being applied.

\begin{equation}
\label{eq:trigonometry_distance_prototype1}
\begin{aligned}
p_1 &= r_1 \cdot \cos(a_1) \\
p_2 &= r_2 \cdot \cos(a_2) \\
d_{total} &= -p_1 + d_0 + p_2 
\end{aligned}
\end{equation}

\bigskip \noindent
The PyBullet's Neo-Hookean model was used for soft-body simulation. While linear models like Hooke's Law can be used to model small strains, materials that undergo large deformations need to use a hyperelastic model that accounts for their nonlinearities. Neo-Hookean is a simple form of hyperelastic model. It is characterized by a strain energy density function, which defines the energy stored in the material due to deformation. The Neo-Hookean model decouples this energy into two parts: deviatoric, which handles shear deformations, and volumetric, which deals with volume changes. The model is configured by material-dependent Lamé parameters that describe the mechanical behavior of isotropic solids. The first Lamé parameter $\lambda$ is related to the volumetric changes, and the second Lamé parameter (shear modulus) $\mu$ is used to describe the material's resistance to shear deformation. Both of these parameters can be calculated \cite{febio2023} from material properties E (Young's modulus) and $\nu$ (Poisson's ratio) (Eq. \ref{eq:lame_parameter_mu}, \ref{eq:lame_parameter_lambda}).

\begin{equation}
\label{eq:lame_parameter_mu}
\mu = \frac{E}{2(1 + \nu)}
\end{equation}

\begin{equation}
\label{eq:lame_parameter_lambda}
\lambda = \frac{E \nu}{(1 + \nu)(1 - 2\nu)}
\end{equation}

\noindent
One study \cite{10637182} has shown that it is possible to predict these parameters using a data-driven model to accurately simulate real-world soft models in PyBullet. It also mentions that soft bodies tend to become unstable (implode or explode) when Lamé parameters are set too low or too high. Another reason for soft-body instability is that the simulation is run in discrete time steps; the lack of fidelity can cause numerical issues during sudden application of large forces. Some solvers use adaptive time stepping to overcome this issue, but such a feature is unavailable in PyBullet. It's a common practice to set PyBullet's time step to 1/250 of a second for rigid body physics simulations, but this value turned out to have poor soft body stability during testing. A value of 1/1000 was used as it yielded much better stability. Another factor that influenced stability was the mesh itself. Multiple softballs were created using icosphere mesh with varying subdivision settings (Fig. \ref{fig:ball_subdivissions}). Increasing subdivisions increases the resolution of the mesh, making the ball appear smoother, but it also increases the vertex count, potentially making soft body simulation slower. A ball with 2 subdivisions was used as it yielded the best performance and stability while still maintaining its round shape.

\bigskip \noindent
The normal forces between the softball and gripper pads are obtained using PyBullet's function getContactPoints. The reaction forces $Rl$ and $Rr$ in PyBullet are assumed to be distributed symmetrically and can be represented with total resultant force as a sum of individual forces at the centroid of the contact area. In order to achieve the force feedback, the reaction forces from the simulation need to be converted to the motor torques (Eq. \ref{eq:motor_reaction_torques}).

\begin{equation}
\label{eq:motor_reaction_torques}
\begin{aligned}
\tau_l &= R_l d_l \\
\tau_r &= R_r d_r
\end{aligned}
\end{equation}

where:
\begin{itemize}
\item \( \tau \) is the motor torque required to exert an equivalent reaction force,
\item \( R \) is the equivalent normal reaction force,
\item \( d \) is the distance between the reaction force and the center of rotation,
\item \( \theta \) is the angle between force and the lever arm.
\end{itemize}

XM540-W270-T/R are smart servo motors; they have several control modes available: Current Control Mode,
Velocity Control Mode,

\subsection{PWM control}
The pulse width modulation (PWM) is a low-level motor control mode. All of the control modes for the Dynamixel motors end up employing PWM control as a final step in their control scheme. PWM control mode gives fine-grain control over the motors if the available control modes are not satisfactory. Additionally, not all motors provide multiple control modes; it is common for direct current (DC) motors to only use PWM control as a means to change the speed of the motor. A PWM signal is a square wave with the signal either being on (set to the maximum voltage) or off (zero voltage). The average voltage delivered to the motor depends on the duty cycle, a ratio of the "on" time to the total period of the signal. The motor used has $PWM \in \mathbb{Z} \cap [-885, 885]$, where 0 would be duty cycle 0\%, 885 duty cycle 100\% in counterclockwise (CCW) direction, and -885 duty cycle 100\% in clockwise (CW) direction.

\begin{equation}
\label{eq:duty_cycle}
V_{out} = V_{max} \cdot DutyCycle
\end{equation}

\bigskip \noindent
The motor torque holds a linear relationship to the supplied current (Eq. \ref{eq:current}), where $k_t$ is the torque constant. In the XM540-W270-T/R motor's datasheet it is written that stall torque for this particular motor is 10.6 [Nm] (at 12.0 [V], 4.4 [A]). Using this information, the torque constant can be calculated: $k_t = \tau / I = 10.6 / 4.4 = 2.409$.

\begin{equation}
\label{eq:current}
\tau = k_t \cdot I
\end{equation}

\bigskip \noindent
The motor measures the supplied current internally and provides a value for it in one of its registers. The objective of the PWM control will be to reach and maintain a goal current as quickly as possible while having minimal steady-state error. This control goal can always be related back to the torque when needed. The PID controller diagram can be seen in Fig. \ref{fig:PID_controller}. The motor's servo arm is placed against a fixed support. The reaction force from the fixed support generates resistance that is measured by the motor in the form of current.

\bigskip \noindent
The PID controller has positional, integral, and derivative gains Kp, Ki, and Kd that need to be tuned. When the transfer function is known, analytical methods such as root locus can be used to systematically tune a closed-loop system's pole locations as a function of PID gains to meet performance and stability requirements. Model-free systems are often tuned manually. Heuristic approaches like Ziegler–Nichols can be used to obtain initial controller parameters. Manual tuning proved to be difficult and time-consuming. It was easy to get stuck in a local minimum, and drastic changes in gains require restarting the tuning process. During this trial-and-error phase, a thought occurred to me. Could an evolutionary algorithm (EA) be employed to automatically tune a PID controller of a model-free system? EA algorithms are inspired by biology and the process of natural selection, where the fittest individuals (those that have better adaptation to their environment) get more chances to reproduce, their offspring have a chance to inherit those strong traits from the genes of their parents, making subsequent generations more adapted to their environment. A member of the population could be initialized with three genes that represent Kp, Ki, and Kd values. If the fitness of the member could be measured using some kind of fitness function, by the process of evolution, crossover, and gene mutation, a variety of PID gains would be tested, and the genes of the strongest individual after simulation would be used as the controller PID values. When the softball in the simulation is squeezed, the reaction forces and thus the target torques/currents will be changing rapidly. Intuitively, a good fitness function should encompass rapid changes. For this reason, a target current is chosen as a step function (Eq. \ref{eq:test_ga}), and the fitness of the individuals will be represented by a sum of absolute errors, meaning the best-performing members of the population will have the lowest tracking error.

\begin{equation}
f(\text{iteration}) =
\begin{cases}
0.2 & \text{if } 600 < \text{iteration} < 1200 \\
0.1 & \text{otherwise, where iteration} \leq 1800
\end{cases}
\label{eq:test_ga}
\end{equation}

\bigskip \noindent
A population of size 150 was initialized. Each member was assigned random Kp, Ki, and Kd values in ranges [0, 1024], [0, 512], and [0, 64], respectively. The algorithm was trained for 20 generations with a mutation rate of 0.1. The top-performing member of the population has the PID gain values Kp = 28.809, KI = 503.211, and KD = 0.191. This member obtained the fitness value of 2.295. This is a significant improvement, as the PID values obtained from the trial-and-error approach have a fitness value of 8.824. 

\bigskip \noindent
After the training, the PID controller was tested against a more varied target function that includes triangle and sinusoidal waves (Fig. \ref{fig:ga_testing_function}). The controller is able to follow the target quite well; the fitness for this function is 54.8. On average for this testing function, the present current reaches the goal current after 17 iterations, which equates to 131.059 ms, with the average iteration time being 7.709 ms.

\bigskip \noindent
The exoskeleton was also tested by squeezing the virtual ball in the simulation. The sensation subjectively feels convincing, but looking at Fig. \ref{fig:ga_squeeze_ball}, it is evident that there is a significant delay in the reaching target current. This could be the result of the PID gains trained to maintain a torque against a fixed support, but human fingers are less rigid, and the forces from the user squeezing and releasing motor finger pads quickly only act as an additional disturbance. Note that the controller is disengaged when the target current is zero; otherwise, the PWM controller generates resistance instead of being in a freewheeling condition. This results in somewhat suboptimal behavior at the moment the PID controller is switched on, as the integral term is time dependent and it is being reset.

\subsection{Current control}
This control mode allows the current to be controlled directly. Internally it works similarly to the PID controller implemented in the section above. As seen in Fig. \ref{fig:current_control_test}, when tested, this controller achieves superior performance compared to the implemented PWM control, with fitness (sum of absolute errors) being 18.823 (the PID had 54.8) and reaching target current in less than 8 ms (one iteration; exact time is unknown as it is impossible to measure faster). This performance can be attributed to Dynamixel having well-tuned PID loops optimized for their hardware and low-latency feedback due to the motor performing controlling internally without the need for slow communication and signal conversion to the PC.

\bigskip \noindent
It can be seen from Fig. \ref{fig:current_control_5_times_squeeze} that when the virtual ball is being squeezed, the present current follows the target current closely. Although the tracking response is faster, subjectively the experience does not feel as pleasant as when the PID controller was used. It might be due to the rapid changes in the target current during each iteration. The rapid changes in the target current can be seen by taking a closer look at a single squeeze (Fig. \ref{fig:current_no_smoothing}). The signal provided by the simulation is not necessarily smooth or continuous, and the values can be rapidly changing. This issue can be mitigated by processing the signal. Exponential smoothing (Eq. \ref{eq:test_exponential_smoothing}) was chosen to process the signal as it is fast to compute (it does not require storing a list of previous N values; it only depends on the last value) and provides the desirable effect of increased smoothness. A variety of different window size values have been tested and plotted (Fig. \ref{fig:exponential_smoothing_k_variations}). Increasing the window size provides a smoother signal but adds an additional delay. A window size of 10 has been chosen for the final controller, as it seemed like a good compromise between a smooth experience and added delay (Fig. \ref{fig:current_smoothing}). This controller also is set to freewheeling mode when the target current is near zero and has the same problems of maintaining low target currents during the start of the squeezing motion.

\item \( S_{t-1} \) is the previous smoothed value.
\end{itemize}
